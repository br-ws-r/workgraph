# Repository review — September 2026

Scope: all runtime modules, tests, package metadata/lockfile, CI, README and design
documents. Baseline: commit `3554fee`, including the recent OMP and workspace-chat
increments. The objective is a small, portable Cognee–Multica bridge, with OMP as
the primary host direction and continued Pi compatibility.

## Deliberately retained boundaries and remaining work

- **At-least-once delivery:** Cognee does not document an idempotency guarantee for
  the header Workgraph supplies. Exactly-once remote ingestion needs upstream
  support or a separate deduplication design. A timeout is not proof of failure.
- **Operational backend binding:** schema v3 stores workspace provenance, not a
  Cognee origin/tenant binding. Operators must isolate data directories and treat
  endpoint/tenant changes as migrations. Independent deployments sharing slugs
  need separate Cognee tenants/instances. A namespace/migration mechanism is future
  design work, not an arbitrary new environment switch in this refactor.
- **Activity coverage:** baseline gaps require investigation; labels, metadata,
  attachments and arbitrary workspace objects are outside the verified feed.
  No unsupported automatic backfill is introduced.
- **Bounded calls, not bounded lifecycle duration:** Multica commands have per-call
  timeouts, but long parent/list traversal and serialized flushes can make startup
  discovery or shutdown longer than one timeout. Explicit managed scope avoids the
  selector. There is no independent worker or retry timer while agents are idle.
- **No content redaction:** structured validation bounds records and provenance,
  not secrets in user-supplied summaries. This remains an operating responsibility.
- **Upstream compatibility:** host lifecycle tests and native storage/HTTP smoke
  checks cover the declared contracts. The live acceptance check remains necessary
  for a new server, Cognee version, token policy or harness upgrade.
- **Types:** the shared adapter retains a narrow build-time dependency on Pi types
  and documented casts for OMP's differing lifecycle. A second complete host SDK
  abstraction would add maintenance without demonstrated benefit today.
- **No broad rewrite or schema migration:** preserve the working ontology, UUID
  provenance, server hierarchy authority, outbox file and package entrypoints.

## Validation

`npm run check` performs strict source and test typechecking, regression tests, a build and
installation of the packed artifact into a fresh consumer with production-only
dependencies. Package checks cover CLI resolution, public exports, both adapter
entrypoints, native SQL ownership/baselines, multipart delivery and recall over a
real loopback HTTP server. `node scripts/package-smoke.mjs --bun` repeats the runtime
contract under Bun. CI runs the same package path on Node 22.19.0, Node 24 and
Bun 1.3.14. `npm audit --omit=dev` checks the installed runtime dependency tree.

The review does not certify live production credentials, all Multica/Cognee
versions, multi-host exact timeline aggregation, or inference-provider behavior.
Use the documented [acceptance check](deployment.md#acceptance-check) for the
actual deployment. No package was published and no existing deployment was changed.
